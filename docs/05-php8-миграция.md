Дата: 11.11.2026.

## 1. Архитектура (изолированный PHP для staging)

Прод и staging теперь работают на **разных** версиях PHP, не мешая друг другу:

| Площадка | Схема | PHP |
|---|---|---|
| Прод `bobrovylog.ru` | nginx → Apache (mod_php) → `/home/bitrix/www` | **7.4.33** |
| Staging `stage.bobrovylog.ru` | nginx → php-fpm → `/home/bitrix/stage` | **8.1.29** |

- Установлены пакеты remi: `php81-php-{cli,common,gd,mbstring,mysqlnd,opcache,xml,zip,intl,sodium,bcmath,ldap,pdo,fpm}`, `php81-php-pecl-{apcu,memcache}`.
- php-fpm 8.1 слушает `127.0.0.1:9001`, пользователь `bitrix`, автозапуск включён.
- `/etc/opt/remi/php81/php.d/99-bitrix.ini`: `short_open_tag=On` (критично для Битрикса), `memory_limit=512M`, `upload_max_filesize=64M`, opcache, `date.timezone=Asia/Krasnoyarsk`, **`mysqli.default_socket=/var/lib/mysqld/mysqld.sock`** (иначе PHP 8 не находит MySQL).
- nginx staging: `location ~ \.php$ → fastcgi_pass 127.0.0.1:9001`, `try_files $uri $uri/ /index.php?$query_string`, запрет выполнения PHP в `/upload`, `/bitrix/cache`, `/bitrix/backup`.
- Apache-виртуалхост staging удалён — Apache обслуживает только прод.

### 3.1. Систематическое исправление свойств «строка вместо массива» (найдено позже)

При расширенном обходе обнаружились ещё 65 обращений вида `["~VALUE"]["TEXT"]` в 20 файлах — при строковом значении свойства это фатал PHP 8.
Во **всех** местах обращение заменено на безопасное выражение:

```php
(is_array($arItem["PROPERTIES"]["CODE"]["~VALUE"])
    ? $arItem["PROPERTIES"]["CODE"]["~VALUE"]["TEXT"]
    : $arItem["PROPERTIES"]["CODE"]["~VALUE"])
```

Итого: 49 замен в 13 шаблонах + 4 в `bitrix/php_interface/init.php` (14 файлов). Правка побайтовая — кодировка файлов не изменялась, проверена `php -l`.
Исправления выложены на staging, затем на прод; все разделы (включая `/about/tenders/`) — 200 на обеих площадках.

## 5. Важно: инцидент с vhost (11.11.2026)

При создании staging Apache-виртуалхост `bx_ext_stage.bobrovylog.ru.conf` сортировался раньше `default.conf` и стал **виртуалхостом по умолчанию** для `127.0.0.1:8888` — трафик прода пошёл в staging, затем на ~11 минут (15:49–16:00) прод отдавал 503. Исправлено: staging вынесен в nginx+php-fpm, Apache-виртуалхост staging удалён.

Сверка баз после инцидента: счётчики и максимальные timestamps `b_iblock_element`, `b_file`, `b_user`, `b_event` и др. **полностью совпадают** — данные прода и staging не разошлись, потерь нет.
