## 2. Как восстановить сплит-архив

```bash
cd /home/bitrix/www/bitrix/backup
# собрать части в один архив: сначала базовый файл, затем .1, .2, … .85 по порядку
cat bobrovylog.ru_20260110_143740_full_l20ndx1fyyqouzw0.tar.gz \
    bobrovylog.ru_20260110_143740_full_l20ndx1fyyqouzw0.tar.gz.1 \
    bobrovylog.ru_20260110_143740_full_l20ndx1fyyqouzw0.tar.gz.2 \
    ... \
    bobrovylog.ru_20260110_143740_full_l20ndx1fyyqouzw0.tar.gz.85 \
    > full-backup.tar.gz
tar xzf full-backup.tar.gz -C /
```

Внутри архива Битрикса — файлы сайта и дамп БД. Восстановление на живой сайт делать только на staging, затем переносить проверенное.

## 3. Текущая схема резервного копирования

1. **Перед рискованными работами** (обновление ядра, PHP, массовые правки) — `deploy/backup-prod.sh` на сервере:
   дамп БД + архив кода в `/root/backups/` (пример: `db-sitemanager-20261111-165853.sql.gz` 12 МБ + `site-code-20261111-165853.tgz` 845 МБ).
2. **Раз в месяц** — переносить свежий бэкап с сервера на локальную машину/внешний носитель и удалять с сервера.
3. **Локальные копии** — хранить минимум в двух местах (диск + внешний носитель/облако).
4. Бэкапы создаются **без** `upload` (9.5 ГБ медиа) и `bitrix/backup` — при восстановлении медиа-библиотека восстанавливается отдельно.

## 4. Замечания

- Полный бэкап от 10.01.2026 — единственный доступный на тот момент; после его удаления с сервера на проде нет «горячего» бэкапа Битрикса, есть только снимки `/root/backups` (11.11.2026).
- В локальной копии сохранять и файл `sha256-server.txt` (передан в `docs/backup-sha256-2026-01-10.txt`) — он подтверждает целостность.
