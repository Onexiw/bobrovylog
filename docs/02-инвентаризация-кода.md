## 3. Что делает init.php (важно для правок)

- Подключает сторонний модуль `wsrubi.smtp` (SMTP-почта).
- Определяет `d()` — отладочный вывод через `print_r` только для админа.
- `LOG_FILENAME = $_SERVER["DOCUMENT_ROOT"]."/mx_log.txt"` — лог пишется **в корень сайта**.
- Обработчики `OnAfterIBlockElementAdd/Update` для инфоблока **ID 8 «Объекты на карте»** — перегенерируют JSON-файлы карты при изменении элементов.
- `.access.php` в корне — права доступа Битрикса по разделам.

## 4. Риски и находки

1. **PHP 7.4 EOL** — обновление обязательно; делать поэтапно, с проверкой кастомных компонентов.
2. **Битрикс 23.300.0** — сильно отстаёт; обновление ядра требует staging.
3. **Три копии компонента расписания** (`_mibok`, `mx_mibok`, `mibok copy`) — высокий риск править не ту версию.
4. Кастомные компоненты лежат в `/bitrix/components`, а не в `/local/components` — их может затронуть обновление ядра.
5. Дубли/бэкапы в шаблоне: `footer(1).php`, `footer.php.bak`, `footer.php.bak_t25` — риск правки в устаревшем файле.
6. `mx_log.txt` в docroot — может быть доступен извне (`/mx_log.txt`), проверить и закрыть.
7. `knopka-2.php` — пустой файл в проде.
8. Имена файлов с двойной кодировкой (`services/*.pdf`, `index русский…`) — наследие переноса с Windows-хостинга; в git попали как есть.
9. `www.bobrovylog.ru` не резолвится (только основной домен).
10. Вход по `root` с паролем — после настройки ключа пароль рекомендуется сменить.
