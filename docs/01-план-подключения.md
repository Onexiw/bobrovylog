# План подключения кода bobrovylog.ru

## Что нужно от владельца (заказчика)

1. **Доступ к файлам сайта** — один из вариантов:
   - SSH на хостинг data-pool: хост, порт, логин, пароль (или публичный ключ, который я сгенерирую);
   - SFTP (тот же SSH), если выделен отдельный аккаунт;
   - панель хостинга (ISPmanager/cPanel) с доступом к файловому менеджеру и созданию SSH;
   - полный архив сайта (`tar.gz`/`zip`), если выгрузка руками невозможна.
2. **Доступ в админку Битрикса** (https://bobrovylog.ru/bitrix/admin/) — логин/пароль администратора.
3. **Контакты того, кто сейчас поддерживает хостинг** (data-pool / ИТ-департамент) — на случай прав/лимитов.
4. **Ответ по тестовому контуру**: есть ли staging, или все правки идут на прод с бэкапами.

## Этапы

### Этап 0. Доступы (сейчас)
- Получаем SSH/SFTP, генерируем ключ, проверяем подключение.
- Фиксируем в `_local/access.json` (вне git).

### Этап 1. Полная выгрузка кода
- Забираем весь сайт, **исключая** `bitrix/cache`, `bitrix/managed_cache`, `bitrix/backup`, `upload/resize_cache`, `upload/tmp` (это десятки ГБ кэша, не нужны).
- `site/` = снимок «как есть с прода»; фиксируем дату и хеши.
- Инициализируем git: первый коммит — чистый прод, дальше — только наши правки.

### Этап 2. Инвентаризация
- Карта кастомного кода: `/local/` (шаблоны, компоненты, модули), `mibok/rasp.timetable.list`, правки в `/bitrix/` (если есть — их видно только на сервере).
- Список инфоблоков, которые правятся руками, и куда лучше лезть через админку, а не через файлы.
- Проверка версии ядра Битрикса, PHP-версии, MySQL.

### Этап 3. Рабочий цикл правок
1. Правка в `site/` (ветка git).
2. Проверка: `php -l` по изменённым файлам (+ локальный просмотр, если поднимем копию).
3. Бэкап затрагиваемых файлов на сервере (`_backup/<дата>/`).
4. Выгрузка только изменённых файлов.
5. Запись в `docs/журнал-изменений.md`.

### Этап 4. Тестовый контур (желательно)
- Копия сайта на поддомене (`stage.bobrovylog.ru`) с отдельной БД — проверяем правки до прода.
- Нужны: MySQL-доступ и возможность создать поддомен/БД.

### Этап 5. Модернизация (по приоритетам заказчика)
Кандидаты, уже видные снаружи:
- `www`-зеркало не работает → настроить 301 на основное имя.
- HSTS + современные security-заголовки.
- jQuery 1.12.4 (2016) — обновление или отказ.
- Сторонние скрипты (`moipass`) — проверить влияние на скорость.
- Обновление версии Битрикса (осторожно: кастомный `mibok`-компонент).
